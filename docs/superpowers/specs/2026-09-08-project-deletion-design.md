# 项目永久删除设计

## 背景

当前 v2 Web 项目列表只提供读取和进入项目的入口，没有删除交互，也没有对应的应用服务和 HTTP 接口。用户需要能够清理已有的本地项目。

## 目标

- 在项目列表为每个项目提供明确的“删除”入口。
- 删除前在浏览器中显示项目名并要求二次确认。
- 删除整个受管工作区目录，包括 `profile.json`、`.rflp` 模型数据和 `inputs` 文件。
- 删除成功后返回项目列表；项目不存在时返回明确的 404 错误。
- 防止通过项目名路径穿越到受管工作区之外。

## 设计

### Web 交互

项目卡片增加危险样式的删除按钮。按钮提交 `DELETE /projects/{project_id}` 前由浏览器原生确认框提示：项目名、永久删除和不可恢复性。确认取消时不发送请求。

### 应用与接口

`ProjectService` 增加 `delete(project_id)`，先通过现有 `managed_workspace()` 校验项目标识和根目录边界，再确认目标是受管工作区目录，最后递归删除目录。`resource_api` 增加 `DELETE /projects/{project_id}`，成功返回 `{status: "ok", project_id: ...}`，并复用现有错误格式。

项目列表页使用一个轻量脚本提交 JSON 无关的 DELETE 请求，成功后跳转 `/ui/projects`，失败则在卡片内显示错误，不吞掉服务端响应。

### 安全边界

- 只允许删除当前配置的 workspace root 下、且通过 `managed_workspace()` 校验的项目名。
- 不接受任意路径作为删除参数。
- 不提供批量删除、软删除或跨项目删除接口。
- 浏览器确认只保护交互误操作；服务端仍独立执行路径校验。

## 验收标准

1. 项目列表展示删除按钮，点击取消不会改变项目。
2. 点击确认后，项目目录及其内容被移除，列表不再显示该项目。
3. 删除不存在的项目返回 404/统一错误响应。
4. `../`、路径分隔符等非法项目标识不能触发目录删除。
5. Web 页面、API、应用服务和现有完整测试全部通过。
