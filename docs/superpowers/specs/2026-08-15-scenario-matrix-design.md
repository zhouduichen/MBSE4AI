# 场景矩阵与折叠详情设计

## 目标

在“提交并分析”完成后，自动生成多个可执行场景，而不是只生成一个最小占位场景。场景继续写入现有场景模块，并与需求、利益相关方和 MBSE 顺序图保持关联。

## 用户体验

- 默认生成约 12–20 个场景，覆盖正常、异常、故障和应急类别。
- 场景按任务阶段和运行条件展开，至少覆盖起飞/巡航/降落/患者交接、天气/能见度、通信/导航、医疗紧急程度和降级处置等维度。
- 场景页面默认折叠显示多个卡片；卡片头部显示标题、场景类型、阶段、状态和关联需求数量。
- 点击卡片后展开参与者、前置条件、触发条件、步骤、预期结果、故障/异常、环境维度和关联 Requirement ID。
- 场景默认自动接受，可继续编辑、执行声明性轨迹或打开 MBSE 顺序图。
- 不新增独立的“智能补全”入口；场景矩阵属于现有“场景生成”模块。

## 生成策略

1. 保留现有 `generate_scenario_drafts` 的最小输入兜底，保证无模型时仍有场景。
2. 在统一提交流程中使用领域包的 `scenario_dimensions`、`lifecycle_phases` 和现有需求 Claim，生成去重后的代表性场景组合，而不是完整笛卡尔积。
3. 每个场景包含稳定 ID、来源需求、参与者、前置条件、触发、步骤、预期结果、故障/异常和维度上下文。
4. 场景数量有明确上限，默认 12–20 个；同一需求至少生成一个正常场景、一个异常/故障场景和一个应急/降级场景（适用时）。
5. 生成结果通过现有场景状态保存、编辑、执行和顺序图路由，不改变已有场景 JSON/API 结构。

## 数据与模块关联

- 复用现有 `scenarios` 数组和 `build_scenario`/`revise_scenario` 契约。
- 使用 `requirement_ids` 把场景关联到正式需求；使用 `actors` 对应利益相关方名称。
- 场景维度保存在兼容字段中（描述、上下文或扩展字段），不破坏现有 JSON 导出。
- MBSE 顺序图继续从已接受场景选择进入；默认选中第一个已接受场景。

## 失败与降级

- 没有 LLM 时，领域包和确定性规则仍生成多场景矩阵。
- LLM 返回格式错误时，不清空已有场景；只记录诊断并保留确定性场景。
- 场景生成失败不影响需求、RFLP 和 MBSE 的其他确定性模块。

## 验收标准

- 一句需求提交后，场景模块至少显示多个场景卡片，默认折叠。
- 点击任一卡片能展开完整字段，并能保存编辑、生成执行轨迹和打开顺序图。
- 场景数量落在默认上限内，至少包含正常/异常/故障维度的代表性覆盖。
- 现有场景新增、编辑、删除、审核、执行、JSON 下载和顺序图测试继续通过。
- AI 不可用时仍能看到多场景确定性结果，不出现空场景模块。
