# MBSE 审核页闭环入口设计

## 目标

让 MBSE 语义模型的生成、逐项审核和最终确认全部在 RFLP 图页面完成，不要求演示人员切换到命令行执行重新生成命令。

## 方案

- 复用现有 `POST /w/{workspace_name}/requirements/mbse` 接口，在已有 MBSE 模型时也由页面提供“重新生成草稿”入口。
- 重新生成只创建新的 MBSE 审核版本，保留原始需求和正式 RFLP 模型；生成结果状态为“待确认”，元素状态为候选。
- 逐项审核按钮根据状态显示明确文案：候选项显示“接受/驳回”，已接受项显示“已接受”，已驳回项显示“已驳回”。后两者保持禁用，避免误解为仍可操作。
- 页面测试覆盖：已存在模型时可见重新生成入口，审核状态文案正确，接口提交后模型回到 review 状态。

## 不在本次范围

- 不新增数据库表或修改 MBSE 数据结构。
- 不改变确认规则、导出格式和 RFLP 正式模型生成规则。
- 不引入前端框架或额外运行时依赖。

## 验收标准

1. MBSE 模型已确认时，页面仍可直接点击“重新生成草稿”。
2. 重新生成后页面显示“待确认”，并可点击每个候选元素的“接受/驳回”。
3. 已处理元素的按钮文案准确反映状态，不出现灰色“接受”造成的歧义。
4. 现有 MBSE、Web 页面和全量测试保持通过。
