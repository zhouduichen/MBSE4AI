# AI4MBSE 总体布局与多学科优化轻量化设计

**日期：** 2026-08-09  
**范围：** 客户验收功能 2.1、2.2（M3、M4）  
**前置状态：** M0～M2 已完成首版  
**设计原则：** 最轻量、低耦合、易修改；固定核心字段加领域包扩展字段

## 1. 目标

本阶段交付两个连续闭环：

1. 输入指标包络，检索相似历史方案，生成 3～5 套满足硬约束且相互有区分度的总体布局候选。
2. 对候选批量执行气动、结构、重量/重心学科评估，将结果反馈给优化器并保留完整证据。

固定翼飞行器作为首个验收领域包，但平台核心不包含固定翼专用字段。后续增加航天器、车辆或其他产品时，优先新增领域包和适配器，不修改公共审批、追溯和证据逻辑。

本阶段不包含自然语言 CAD、二维/三维标注和 DFM/DFA；这些属于 M5～M7。

## 2. 方案选择

### 2.1 方案 A：每个领域建立固定数据库表

实现直接、查询方便，但客户增加字段、修改单位或切换产品类型时必须执行数据库迁移并修改代码，不满足“最方便改”的要求。

### 2.2 方案 B：所有数据保存为无约束 JSON

字段变化最自由，但缺少类型、单位、必填项和硬约束验证，难以证明 3～5 套方案真实满足约束，也不利于正式验收。

### 2.3 方案 C：固定核心字段加领域包扩展字段

公共对象只固定身份、版本、状态、来源、哈希和追溯字段；专业参数、单位、约束、映射和目标函数由版本化领域包声明。数据库仍使用现有 SQLite，外部工具通过小型适配器接入。

本设计采用方案 C。

## 3. 最小部署架构

继续使用现有 Python 单体、SQLite、Web/API/CLI 和分层结构，不增加微服务、消息队列、配置中心、向量数据库或独立规则引擎。

```text
Web / API / CLI
       |
概念设计应用服务
       |
+------+------------------+
|                         |
领域包加载与校验       候选/评估/优化编排
|                         |
SQLite JSON 记录       学科适配器端口
                          |
                内置计算 / 客户仿真工具 / 合格代理模型
```

所有状态保存在现有工作区 `<workspace>/.rflp/model.db`。大型草图、日志和工具输出按内容哈希保存在工作区工件目录，SQLite 只保存索引和结构化摘要。

## 4. 领域包

### 4.1 最小文件形态

首版每个领域包只有一个 JSON 文件：

```text
domain-packs/
└── fixed-wing-v1.json
```

文件包含：

```json
{
  "id": "fixed-wing",
  "version": 1,
  "object_type": "aircraft-layout",
  "id_prefix": "FW",
  "parameters": [],
  "derived_parameters": [],
  "constraints": [],
  "mappings": {},
  "retrieval": {},
  "generation": {},
  "objectives": [],
  "disciplines": []
}
```

暂不实现领域包分片、继承和远程注册中心。单文件无法维护时再引入拆分能力。

### 4.2 可配置内容

领域包允许修改：

- 参数名称、客户别名、类型、单位、枚举、默认值和必填状态。
- 客户字段到标准参数的映射、比例和单位转换。
- 派生参数的安全算术公式。
- 硬约束、软约束、阈值、严重程度和提示文本。
- 历史方案检索特征、归一化范围和权重。
- 候选数量、随机种子、扰动范围和最小差异度。
- 目标函数、优化方向和权重。
- 学科适配器名称、版本要求、超时、有效域和回退策略。
- ID 字头和页面显示名称。

### 4.3 不允许领域包修改的内容

领域包不能覆盖：

- 全局对象 ID、内容哈希和修订规则。
- `candidate / accepted / rejected` 等公共审批语义。
- 来源、追溯、证据和审计记录。
- 已批准对象和既有历史修订。
- 权限、安全限制和外部命令白名单。
- “可行”“综合评估通过”等正式状态门禁。

领域包只允许声明式 JSON，不允许包含 Python、Shell、模板表达式或其他任意可执行代码。

### 4.4 领域包切换

项目固定引用 `domain_pack_id + domain_pack_version`。切换领域包或升级版本时：

1. 保留旧修订和旧证据。
2. 建立新的概念设计修订。
3. 重新映射参数、校验约束、检索方案和执行学科评估。
4. 禁止沿用旧领域包产生的 `feasible` 或 `passed` 结论。

## 5. 固定核心对象

### 5.1 SchemeRecord

历史方案的统一记录：

```text
id
object_type
schema_version
domain_pack_id
domain_pack_version
revision
status
source
content_hash
parameters
extensions
```

`parameters` 保存领域包已定义字段；`extensions` 保存客户新增但尚未纳入领域包的字段。扩展字段可以展示和导出，但只有领域包明确引用的字段才能参与约束、检索和仿真。

### 5.2 IndicatorEnvelope

指标包络包含：任务条件、目标值、上下界、固定值、硬约束、软约束、单位、来源需求 ID 和领域包版本。

输入必须先完成字段映射、类型检查和单位归一化。缺失必填参数时停止正式候选生成，并返回逐项诊断。

### 5.3 LayoutCandidate

每个布局候选包含：

- 候选 ID、输入包络 ID 和领域包版本。
- 完整参数及来源：用户输入、参考方案、派生值或生成值。
- 参考历史方案 ID、相似度和特征差异解释。
- 轻量几何原语和确定性 SVG 草图。
- 每项硬约束的计算值、界限、余量和结果。
- 可行性状态和不可行原因。
- 生成器版本、随机种子、输入哈希和结果哈希。

### 5.4 DisciplineEvaluation

每条学科结果包含：

- 候选、学科、指标和单位。
- 适配器名称、工具或模型版本、求解来源。
- 输入哈希、输出哈希、开始/结束状态和日志索引。
- `real_tool / analytical / surrogate` 来源类型。
- 代理模型有效域、验证误差和阈值判定。
- `succeeded / failed / timeout / out_of_domain / cached` 状态。

### 5.5 OptimizationRun

优化记录包含每轮候选、学科结果、目标值、约束结果、帕累托排序、淘汰原因、种子和终止原因。它不覆盖原候选和评估结果，只建立引用。

## 6. 数据格式变化与导入

### 6.1 首版输入

首版内置支持 JSON、CSV 和 SQLite 表。若客户实际样本为 XLSX，再增加一个可选 XLSX 导入适配器，不预先引入重量级数据平台。

### 6.2 映射流程

```text
客户字段
→ mappings 配置查找标准字段
→ 类型转换
→ 单位归一化
→ 必填项与范围校验
→ parameters / extensions
→ 内容哈希与修订登记
```

映射项支持：源字段名、目标参数、源单位、目标单位、比例、默认值和空值策略。常用线性单位转换由平台内置；未知转换明确报错，不猜测。

### 6.3 新增和修改字段

- 新字段可以先进入 `extensions`，无需修改数据库。
- 字段需要参与检索、约束或仿真时，加入领域包 `parameters` 并提升领域包版本。
- 字段改名通过 `aliases/mappings` 兼容，不批量改写历史记录。
- 字段类型或单位语义变化必须提升领域包版本并重新导入或显式迁移。
- 未通过校验的行进入隔离结果，保留行号和错误，不污染正式方案库。

## 7. 功能 2.1：总体布局候选生成

### 7.1 可行性预检查

生成前完成：领域包校验、参数必填校验、单位归一化、上下界一致性和硬约束初检。输入自身矛盾时直接给出不可行核心，不启动无意义搜索。

### 7.2 相似历史方案检索

首版使用加权归一化距离，不引入向量数据库：

```text
distance = Σ(weight_i × normalized_difference_i)
similarity = 1 / (1 + distance)
```

数值、枚举和集合参数分别使用简单确定性差异函数。检索权重和归一化范围来自领域包；每个结果输出逐特征差异解释。

### 7.3 候选生成

生成器以排名靠前的历史方案为锚点，在指标包络和领域包允许范围内进行确定性扰动：

1. 复制用户固定参数。
2. 从参考方案补齐未指定参数。
3. 按种子对可调连续参数和离散参数采样。
4. 计算派生参数。
5. 执行全部硬约束。
6. 使用归一化参数距离过滤过于相似的候选。
7. 收集 3～5 个正式可行候选或达到最大尝试次数。

如果不足 3 个可行候选，系统如实返回现有可行方案和不可行诊断，不用不合格方案补数。`infeasible` 对象可以保存为探索证据，但不能混入正式候选集合。

### 7.4 轻量布局草图

首版不生成 CAD。领域包把参数映射为机身、机翼、尾翼等二维几何原语，由现有服务端 SVG 方式确定性渲染俯视/侧视布局草图。相同参数产生相同 SVG 哈希。

### 7.5 复现性

候选 ID 和结果哈希由以下内容计算：

```text
指标包络规范化值
+ 领域包 ID/版本
+ 历史方案修订
+ 生成器版本
+ 随机种子
```

## 8. 功能 2.2：多学科快速评估

### 8.1 首批三个学科

正式 Profile 固定要求：

1. 气动。
2. 结构。
3. 重量/重心。

性能可以作为第四学科。首版提供轻量本地计算适配器用于开发和闭环测试；正式客户验收时，只有客户认可的真实工具、分析模型或验证合格的代理模型可以产生正式证据。

### 8.2 适配器契约

所有学科适配器实现同一最小接口：

```text
evaluate(candidate, discipline_profile) -> DisciplineEvaluation
```

适配器负责自身输入文件、固定命令、超时和输出解析；应用层只处理结构化契约。适配器不可直接修改候选、工作台或审批状态。

### 8.3 批量任务图

一个候选对应三个独立学科任务。应用层使用 Python 标准库有界线程池并行调度，外部工具进程由适配器使用固定参数启动。

任务支持：

- 输入哈希缓存。
- 独立超时和失败状态。
- 一个任务失败时其他任务继续。
- 失败日志和已完成结果保留。
- 适配器版本变化自动产生新缓存键。

缺失任一关键学科成功结果的候选只能标记 `partial`，不得标记综合评估通过。

### 8.4 代理模型门禁

领域包登记代理模型的输入范围、版本、验证数据哈希、误差指标和允许阈值。运行时：

- 输入在有效域内且误差合格：允许产生带 `surrogate` 标识的结果。
- 输入超出有效域：转交配置的真实工具。
- 没有回退工具：结果为 `out_of_domain`。
- 误差登记缺失或超过阈值：不能产生正式通过证据。

### 8.5 优化反馈

首版不引入新的优化框架，采用有界迭代加确定性帕累托排序：

1. 评估初始 3～5 个候选。
2. 过滤硬约束和关键学科失败对象。
3. 根据领域包目标计算目标向量。
4. 生成帕累托前沿和排序理由。
5. 围绕前沿候选进行下一轮小范围扰动。
6. 达到轮数、评估预算或无改进阈值时停止。

每次新候选仍走完整硬约束和学科评估门禁。

## 9. 状态与审批门禁

### 9.1 候选状态

```text
candidate → feasible / infeasible
feasible → evaluated / partial
evaluated → accepted / rejected
```

只有人工操作可以把综合评估后的候选设为 `accepted`。生成器、仿真工具和优化器不能批准方案。

### 9.2 失效规则

以下变化使下游结果失效并建立新修订：

- 指标包络、领域包版本或约束变化。
- 历史参考方案修订变化。
- 生成器、适配器、工具或模型版本变化。
- 人工修改候选参数。

旧评估结果仍保留为证据，但不能附着到新修订。

## 10. 持久化

继续使用一个 SQLite 数据库，新增通用 `id + payload` 表：

- `domain_packs`
- `scheme_records`
- `indicator_envelopes`
- `layout_candidates`
- `discipline_evaluations`
- `optimization_runs`

不建立按固定翼字段展开的数据库列。高频检索先在应用层对内存中的规范化参数执行；只有真实数据规模证明不足时，才为选定字段增加 SQLite 索引表。

## 11. Web、API 与 CLI

### 11.1 Web

新增一个“总体设计”入口，按同一页面的四个区域组织：

1. 领域包与历史方案导入。
2. 指标包络。
3. 3～5 套候选及草图/约束。
4. 多学科结果、帕累托排序和人工接受。

不建设独立低代码配置平台。领域包 JSON 可下载、校验和重新上传。

### 11.2 API

最小版本化接口：

```text
POST /api/v1/workspaces/{workspace}/domain-packs/validate
POST /api/v1/workspaces/{workspace}/schemes/import
POST /api/v1/workspaces/{workspace}/concept-runs
GET  /api/v1/workspaces/{workspace}/concept-runs/{run_id}
POST /api/v1/workspaces/{workspace}/concept-runs/{run_id}/evaluate
POST /api/v1/workspaces/{workspace}/concept-runs/{run_id}/optimize
POST /api/v1/workspaces/{workspace}/layout-candidates/{candidate_id}/review
```

### 11.3 CLI

首版保留三个命令：

```text
rflp concept import
rflp concept run
rflp concept export
```

`concept run` 一次完成检索、3～5 套生成、学科评估和优化反馈，便于客户验收和 CI 复现。

## 12. 错误处理

- 领域包无效：拒绝启用，列出 JSON 路径和原因。
- 数据行无效：隔离该行，继续导入其他有效行。
- 指标包络矛盾：停止生成，返回冲突约束和参数。
- 可行候选不足：如实返回，不以不可行方案补齐。
- 学科任务失败：保留其他任务结果，候选标记 `partial`。
- 外部工具超时：终止该任务并记录超时，不重用不完整输出。
- 代理模型越界：回退真实工具或标记 `out_of_domain`。
- 领域包切换：新建修订并使旧结论失效，不删除旧证据。

## 13. 安全

- 领域包只允许 JSON 数据和白名单算术操作。
- 外部工具只允许已登记适配器构造固定参数命令。
- 文件路径限定在工作区或适配器批准目录。
- 日志、参数和证据不得记录密钥。
- 导入大小、行数、参数数量、生成尝试次数、并发数和超时均有上限。
- Web 继续默认监听 `127.0.0.1`；公网部署前另行实现身份与权限。

## 14. 测试与验收

### 14.1 领域包可修改性

- 新增扩展字段不修改数据库和平台代码。
- 修改映射或 ID 字头后重新导入得到新规范化结果。
- 升级领域包版本不覆盖旧修订。
- 尝试覆盖核心字段时明确拒绝。

### 14.2 功能 2.1

- 对验收指标包络生成 3～5 套正式候选。
- 正式可行候选硬约束满足率为 100%。
- 每套候选包含完整参数、单位、来源、参考方案、相似度解释和 SVG 草图。
- 每套候选包含输入哈希、领域包版本、生成器版本和种子。
- 相同输入、版本和种子得到相同规范化结果。
- 不可行探索方案不会进入正式集合。

### 14.3 功能 2.2

- 气动、结构、重量/重心三个学科全部进入正式 Profile。
- 每次执行保留求解来源、工具/模型版本、输入哈希、日志和指标。
- 一个学科失败时其他独立任务继续完成。
- 关键学科不完整时综合状态不是通过。
- 代理模型越界或误差不合格时不能产生正式结果。
- 帕累托输出可以追溯到候选、每个学科结果和约束判定。

正式 2.2 验收前，客户必须书面确认气动、结构、重量/重心三个评估来源中哪些可作为正式证据。未获确认的内置轻量计算器仍可完成开发联调，但输出固定标记为开发证据，不能形成正式通过结论。

### 14.4 最小自动化测试

- 领域包 JSON 校验和版本测试。
- CSV/JSON/SQLite 映射、单位转换、未知字段和隔离测试。
- 硬约束、派生参数和冲突诊断测试。
- 相似检索、候选数量、可行性、差异度和确定性测试。
- SVG 哈希确定性测试。
- 三学科适配器契约、缓存、超时、失败隔离和代理有效域测试。
- 帕累托排序和终止条件测试。
- SQLite 持久化、审计、失效和领域包切换测试。
- Web/API/CLI 端到端验收测试。

## 15. 实施分解

### M3.0：公共契约与领域包

交付领域包校验、固定核心对象、SQLite 表和版本门禁。

### M3.1：数据导入与方案库

交付 JSON/CSV/SQLite 导入、字段映射、单位归一化、隔离结果和历史方案检索。

### M3.2：布局候选

交付指标包络、可行性预检查、3～5 套差异化候选、硬约束明细和 SVG 草图，完成 2.1 验收。

### M4.0：学科适配器

交付气动、结构、重量/重心契约和首批轻量适配器；真实验收工具通过相同端口接入。

### M4.1：批量评估

交付并发、超时、缓存、失败隔离、日志和代理模型有效域门禁。

### M4.2：优化反馈与验收

交付有界迭代、帕累托排序、人工接受、Web/API/CLI 和完整验收证据，完成 2.2 验收。

## 16. 明确暂缓项

本阶段不建设：

- 微服务和分布式队列。
- 向量数据库和独立特征平台。
- 通用低代码规则引擎。
- 领域包继承、在线市场和远程热加载。
- 三维 CAD 布局和高保真网格生成。
- 自动批准总体方案。
- 未经客户批准的代理模型正式验收结论。

这些能力只有在真实数据规模、并发或工具要求证明当前设计不足时再增加。
