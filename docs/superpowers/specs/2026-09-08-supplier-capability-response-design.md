# 智能研发平台外协供应商能力回复设计

## 文档目标

形成一份面向科室或项目组的简短能力回复，用一至两页说明现有 AI4MBSE 项目对需求清单的覆盖情况，并区分当前能力、可扩展能力和暂未覆盖能力。文档不将研究基础或接口可扩展性表述为已经完成的工程产品能力。

## 读者与语气

读者为智能研发平台项目负责人、需求提出方和供应商遴选人员。采用正式、克制、便于复制到技术交流材料中的书面语，以“我方”陈述能力，不虚构客户案例、性能指标、专业软件适配成果或交付承诺。

## 内容结构

1. 标题：智能研发平台智能体功能需求能力回复。
2. 开篇结论：我方能力以需求分析和 MBSE 模型化闭环为核心，同时覆盖文档智能、知识检索、结构化 AI 推理、规则校验和工具编排等非 MBSE 共性技术；总体布局、专业仿真、CAD 自动建模与工艺审查需要联合专业工具和数据继续集成。
3. 能力对应：按需求分析、总体概念设计、详细结构设计三个阶段逐项回复。每项标识为“当前已具备”“具备基础可扩展”或“暂未直接覆盖”。
4. 总体结论：建议以需求分析与用例建模为首期落地范围，以统一模型、证据、追溯和接口框架支撑后续专业智能体接入。

## 能力判定原则

- 当前已具备：现有代码、测试或项目状态文档能够直接证明的能力，包括 Word 和 PDF 文档接入、结构化模型、需求到运行闭环、证据追溯、门禁检查、局部修复、Web 与命令行入口、JSON SVG DOT 和 SysML lite 导出。
- 具备基础可扩展：已有通用数据模型、知识检索、结构化模型调用、插件式端口或方法论工作流基础，但尚未完成指定专业软件或专业算法闭环。
- 暂未直接覆盖：当前 Core 明确排除或仓库没有验收证据的能力，包括 Concept MDO、真实仿真、CAD 自动建模、二维三维自动标注、可制造性和可装配性几何审查。

## 版式

采用两页以内的正式 Word 文档。Letter 纵向，黑色标题，深蓝色小标题，正文 11 磅左右。能力对应部分使用三列表格呈现“需求功能、能力状态、我方回复”，避免复杂装饰和大面积底色。

## 验收标准

- 每个功能点 1.1 至 3.3 均有明确回复。
- 明确回答“除 MBSE 外是否有涉猎”。
- 当前能力与规划能力边界清晰，无未经验证的实现声明。
- 成稿控制在一至两页，Word 渲染后无截断、溢出或分页异常。
