# 1.x/2.x 客户验收需求树收口设计

**日期：** 2026-09-01  
**范围：** 外协供应商功能点 1.1、1.2、2.1、2.2  
**明确不包含：** 3.1 自然语言 CAD、3.2 PMI/GD&T、3.3 DFM/DFA

## 目标

把现有“每个阶段一条长句”的验收样例改为可逐条判定的原子需求树。正式 Gold 仍使用 v3 兼容契约，但增加树节点元数据、验收方式和证据要求；实际需求输出继续由原文来源锚点配对，不依赖动态区域 ID。

## 验收树

树根只包含四个客户功能：1.1 文档需求捕获、1.2 MBSE 用例辅助、2.1 总体概念布局、2.2 多学科快速评估。每个功能拆成原子条款：

- 1.1：Word/PDF 导入、页/区域解析、实体提取、属性提取、显式约束提取、隐含约束建议、MBSE 需求映射、追溯矩阵。
- 1.2：场景识别、Use Case 框架、Activity 框架、Sequence 框架、人机修改、端到端追溯。
- 2.1：指标包络输入、历史方案检索、3～5 套候选、硬约束满足、参数化二维顶/侧视草图、来源与参数差异证据、候选差异性。
- 2.2：轻量工具/ROM 调用、气动/结构/重量重心三学科、批量执行、失败隔离、缓存、指标汇总、优化器反馈、证据状态治理。

3.x 不出现在正式需求语料、Gold、验收树或通过条件中。

## Gold v3 扩展

每个原子 Gold 记录保留 `key`、`statement`、`accepted_statements`、`source_anchor`、`details`，并增加：

- `parent_key`：树节点父功能键；
- `level`：原子条款层级；
- `area`：`1.1`、`1.2`、`2.1` 或 `2.2`；
- `acceptance_method`：`document`、`mbse`、`concept` 或 `orchestration`；
- `evidence`：该条款必须在验收报告中出现的证据字段。

Gold 根增加 `tree` 数组，声明四个父节点及其子键。加载时校验子键存在、父键匹配、层级合法、每个原子键只出现一次；旧测试构造的最小 v3 Gold 仍可读取，缺省元数据使用兼容默认值。

## 报告与边界

需求验收报告新增 `acceptance_tree`，按父功能汇总 expected/matched/missing/extra 和每个节点的状态。完整 Gold 的正式状态仍受 precision、recall、详情 F1、来源完整率和 MBSE 门禁控制。概念设计验收继续单独报告 2.1/2.2，2.2 内置评估器保持 `development_only`。

## 测试与交付

新增契约测试覆盖树校验、缺失/重复子键、3.x 排除和报告汇总；端到端样例使用原子需求文本运行 CLI，要求 Gold v3 正式通过且四个父节点全部覆盖。文档补充 Word/PDF、数字/扫描 PDF 的验收样本准备清单，但不把临时二进制样本混入源码包。
