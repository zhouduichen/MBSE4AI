# AI4MBSE 客户验收能力建设总体设计

**日期：** 2026-08-08

**状态：** 待用户书面复核
**适用版本：** RFLP-Lite 0.1.0 后续演进版本

## 1. 目标与约束

本项目以客户给出的七项功能要求为硬性验收基线，建设覆盖需求分析与论证、总体概念设计与布局、详细结构设计与产品建模三个阶段的智能研发平台。现有 RFLP-Lite 作为治理和追溯底座继续演进，不将固定演示数据、静态占位页面或未连接真实工具的模拟结果计入功能验收。

必须实现的客户功能如下：

1. 1.1 基于文档的需求自动捕获与结构化。
2. 1.2 MBSE 用例模型智能辅助构建。
3. 2.1 基于约束的总体布局参数自动生成。
4. 2.2 多学科快速评估智能体。
5. 3.1 基于自然语言交互式的三维模型智能生成。
6. 3.2 二维、三维模型的智能生成与标注。
7. 3.3 设计规则智能审查。

项目级约束：

- 默认支持内网、本地化部署，工程数据不得因智能分析而自动上传到未授权外部服务。
- AI 只能生成候选、建议或执行计划，不能自动批准需求基线、总体方案或正式设计模型。
- 所有正式结果必须关联输入、工具版本、模型版本、参数、人工决策和可下载证据。
- CAD、MBSE、OCR、仿真和优化能力均通过明确的端口与适配器接入。
- 详细设计最终验收必须至少连接一种客户认可的真实 CAD 软件；演示适配器只用于开发测试。
- 总体评估最终验收必须使用真实学科工具，或使用经过真实工具样本验证并达到约定误差上限的降阶模型。
- 本规格给出的数值指标作为项目内部验收下限；客户提出更严格指标时采用客户指标。

## 2. 范围分解

整体工作拆为一个公共底座和三个可独立验收的业务子系统。

### 2.1 公共底座

公共底座负责统一对象标识、版本、审批、追溯、证据、权限、审计、任务执行和工具注册。它不包含特定学科算法，但为三个业务子系统提供一致的运行规则。

### 2.2 需求与 MBSE 子系统

负责文档解析、OCR、需求候选提取、需求审核、标准需求生成、追溯矩阵、作战场景和 Use Case/活动图/时序图模型。

### 2.3 总体设计与多学科子系统

负责历史方案检索、指标包络、参数化布局候选、硬约束校验、学科计算、代理模型、多目标优化和方案决策证据。

### 2.4 详细设计与审查子系统

负责设计意图理解、澄清对话、CAD 操作计划、参数化建模、二维图纸、三维 PMI、GD&T 建议以及 DFM/DFA 审查闭环。

## 3. 建设方案选择

### 3.1 方案 A：在现有单体流程内直接扩展

优点是首批页面交付快。缺点是文档处理、仿真调度和 CAD 执行的失败边界不同，继续集中在现有工作台会迅速放大耦合，难以替换外部工具和独立验收。

### 3.2 方案 B：统一领域底座与可替换适配器，分阶段闭环交付

该方案保留现有领域层、应用层、端口和适配器结构，将三个子系统实现为独立应用模块，共享治理对象和证据模型。每个外部工具都有模拟适配器和真实适配器，但只有真实适配器或经批准的代理模型可产生正式验收证据。

这是本设计采用的方案。它兼顾现有代码复用、内网部署、真实工具集成和分阶段验收。

### 3.3 方案 C：直接采购多个专业产品并以门户聚合

该方案单项能力成熟，但需求、仿真、CAD 和审查之间的对象标识、版本和追溯容易割裂，二次集成成本不可控。本项目可以调用商业软件，但不采用只有页面跳转、没有统一数据契约的门户聚合方式。

## 4. 总体架构

```text
Web / CLI / Versioned API
            |
Agent Orchestration and Human Review
            |
------------------------------------------------------------
Requirements & MBSE | Concept & MDO | CAD & Design Review
------------------------------------------------------------
            |
Unified Model / Baseline / Trace / Evidence / Job / Audit
            |
------------------------------------------------------------
OCR | LLM | MBSE | Repository | Solver | CAD | DFM/DFA Ports
------------------------------------------------------------
            |
Local files / SQLite / approved external engineering tools
```

调用方向必须保持向内依赖：接口层和适配器层依赖应用端口，应用服务依赖领域模型，领域模型不依赖外部工具 SDK。外部工具故障不得绕过应用服务直接修改正式基线。

## 5. 统一领域对象

### 5.1 文档与需求对象

- `EngineeringArtifact`：文件标识、哈希、格式、密级标签、版本和导入时间。
- `DocumentPage`：页码、宽高、渲染图哈希和 OCR 状态。
- `DocumentRegion`：页内坐标、段落/表格/图片类型、原文和识别置信度。
- `ExtractedEntity`：实体类型、名称、属性、单位、来源区域和置信度。
- `RequirementCandidate`：主体、义务词、行为、条件、性能指标、约束、验证方法、来源和推断类型。
- `StandardRequirement`：正式需求编号、名称、陈述、类型、优先级、状态、责任对象和验证方法。
- `TraceLink`：源对象、关系类型、目标对象、生成方式、审批状态和证据标识。

### 5.2 MBSE 场景对象

- `Actor`：参与者名称、类别、职责和来源。
- `UseCase`：目标、主参与者、前置条件、触发条件、主成功场景、备选场景和后置条件。
- `ActivityNode`、`ActivityEdge`：动作、决策、并发、开始/结束及控制流。
- `Lifeline`、`Message`：交互对象、消息顺序、同步类型、输入输出和关联需求。
- `MbseModelRevision`：模型格式、版本、元素集合、关系集合和审批状态。

### 5.3 总体设计对象

- `IndicatorEnvelope`：指标名称、上下界、单位、硬/软约束和权重。
- `HistoricalConcept`：历史方案参数、适用任务、性能结果、数据质量和访问权限。
- `SimilarityResult`：参考方案、相似度、命中特征和不适用因素。
- `LayoutCandidate`：候选编号、参数集、几何草图、来源依据和约束状态。
- `DisciplineEvaluation`：学科、工具、输入哈希、输出指标、误差说明、日志和状态。
- `OptimizationIteration`：候选集合、目标函数、约束、帕累托等级和停止原因。

### 5.4 详细设计对象

- `DesignIntent`：自然语言指令、目标零部件、参数、材料、连接方式和上下文模型。
- `ClarificationQuestion`：歧义项、允许选项、推荐项、依据和回答状态。
- `CadOperation`：白名单操作类型、参数、依赖、预期结果和回滚标识。
- `CadExecutionPlan`：有序 CAD 操作、风险、预览结果、人工批准状态和执行状态。
- `CadModelReference`：CAD 系统、文档标识、版本、文件哈希和单位制。
- `DrawingAnnotation`：二维/三维标注类型、目标特征、数值、基准、标准和布局边界。
- `DesignFinding`：规则编号、严重程度、模型位置、证据、建议、责任人和闭环状态。

所有对象采用稳定 ID 和不可变修订号。正式基线引用具体修订，不覆盖历史版本。

## 6. 外部工具端口

### 6.1 文档端口

- `DocumentParserPort`：接收本地文件，返回页、区域、表格和图片结构。
- `OcrPort`：接收页图或区域图，返回文字、坐标和置信度。
- `RequirementInferencePort`：接收受控文本片段和领域词表，返回结构化候选，不直接写入正式需求。

### 6.2 MBSE 端口

- `MbseExchangePort`：导入、导出 Use Case、活动、时序和需求关系。
- `DiagramRendererPort`：从语义模型渲染 SVG/PNG；图片不是模型真源。

### 6.3 总体与仿真端口

- `ConceptRepositoryPort`：检索经过授权的历史方案并返回相似性依据。
- `LayoutGeneratorPort`：根据指标包络和参考方案生成参数化候选及二维/三维轻量草图。
- `DisciplineSolverPort`：执行一个学科的真实计算并返回标准化指标和日志。
- `ReducedOrderModelPort`：执行已注册的代理模型并报告版本、训练范围和预测不确定度。
- `OptimizerPort`：根据候选和学科结果执行多目标优化。

### 6.4 CAD 与审查端口

- `CadPort`：读取模型摘要、预览操作计划、执行白名单参数化操作、保存新版本和回滚。
- `DrawingPort`：生成二维视图、三维 PMI，并放置尺寸、公差和基准。
- `DesignRulePort`：读取可计算几何和装配关系，执行规则并返回定位明确的问题。

每个端口都必须提供能力发现，明确软件名称、版本、许可证状态、支持的操作、单位制和限制。调用方不得根据适配器名称推测能力。

## 7. 功能设计

### 7.1 功能点 1.1：基于文档的需求自动捕获与结构化

处理流程：

1. 导入 DOCX、文本 PDF 或扫描 PDF，计算哈希并创建不可变 Artifact 修订。
2. 文档解析器恢复页、段落、表格、标题和图片区域；扫描区域调用 OCR。
3. 规则与模型协同提取实体、属性、单位、指标、条件、否定词、显式约束和隐含约束候选。
4. 将结果映射为标准需求字段，并区分 `explicit`、`inferred` 和 `manual`。
5. 人工逐条接受、修改或驳回。隐含约束不得批量自动批准。
6. 生成 Artifact→Region→Entity/Constraint→Requirement→Verification 的初版追溯矩阵。

失败处理：无法解析的页保留页图和错误；OCR 低置信度区域进入人工校对队列；单位冲突、上下界冲突和重复需求形成独立问题，不静默合并。

### 7.2 功能点 1.2：MBSE 用例模型智能辅助构建

系统从已批准需求和候选作战场景生成 Actor、Use Case、活动和消息交互建议。场景模板只提供结构，不替代需求证据。用户可编辑节点、关系、顺序和异常分支；每次编辑生成模型新修订并重新计算追溯完整性。

系统至少提供：

- Use Case 图及结构化用例规约。
- 主流程、备选流程和异常流程活动图。
- 参与对象、调用顺序、输入输出和异常响应时序图。
- 模型 JSON、SVG 和客户约定 MBSE 交换格式。

### 7.3 功能点 2.1：基于约束的总体布局参数自动生成

用户提交指标包络、任务条件、载荷、尺寸重量及学科约束。系统进行单位归一化和可行性预检查，然后检索相似历史方案。生成器以参考方案和约束为输入，形成 3～5 个相互有区分度的候选。

每个候选必须包含：

- 完整参数表、单位和参数来源。
- 参考历史方案及相似度解释。
- 可下载的布局草图或轻量几何表示。
- 每项硬约束的满足/违背值。
- 生成算法、随机种子、模型版本和输入哈希。

硬约束不满足的对象可以作为探索方案保存，但必须明确标记 `infeasible`，不能进入正式可行方案集合。

### 7.4 功能点 2.2：多学科快速评估智能体

评估编排器根据候选和 Profile 生成学科任务图，支持并行执行、超时、重试、缓存和失败隔离。真实工具与代理模型输出采用同一 `DisciplineEvaluation` 契约，但证据明确标识求解来源。

首个正式验收 Profile 至少包含气动、结构、重量/重心三个学科；性能学科可作为第四学科配置。优化器接收成功的学科结果、目标函数和约束，生成迭代记录和帕累托候选。缺失关键学科结果的候选不得标记为综合评估通过。

代理模型只有在输入位于有效域且验证误差未超过登记阈值时才可生成正式结果；否则自动转交真实工具或标记无法评估。

### 7.5 功能点 3.1：基于自然语言交互式的三维模型智能生成

自然语言输入先转换为 `DesignIntent`，再生成 `CadExecutionPlan`。系统在以下情况必须反问：目标零件不唯一、尺寸或单位缺失、参考基准不明确、多个结构方案均可行、操作会破坏已有依赖或违反硬规则。

计划批准前只允许读取模型和生成预览。批准后，CAD 适配器逐项执行白名单操作并保存新版本。任何操作失败都停止后续依赖操作，并提供失败位置、CAD 返回信息和可恢复版本。

结构选型建议必须引用标准件、材料或典型结构记录，显示适用条件，不将模型自行生成的理由当作行业规范。

### 7.6 功能点 3.2：二维、三维模型的智能生成与标注

标注服务从 CAD 特征、装配关系、关键特性清单和选定标准生成标注建议。二维工程图和三维 PMI 共享同一语义标注对象，避免各自维护不同数值。

布局器检测文字、尺寸线、视图边界和已有标注的重叠，并通过候选位置搜索实现智能避让。尺寸、公差、形位公差和基准在提交 CAD 前显示标准依据和推荐理由，设计师可编辑或拒绝。

### 7.7 功能点 3.3：设计规则智能审查

规则库按标准、企业、产品和项目分层，规则具有唯一编号、版本、适用对象、严重程度、输入要求、计算逻辑和修复建议。首批规则覆盖：

- 零部件与装配干涉。
- 最小壁厚、圆角半径和孔边距。
- 装配间隙与工具可达性。
- 标准件和材料适用性。
- 基准、尺寸链及关键特性完整性。
- 加工方向、不可达区域和典型不可制造特征。

审查输出必须定位到零件、特征或几何区域。问题支持确认、误报、指派、修复、复核和关闭状态，不允许重新运行后静默消失。

## 8. 数据流与状态门禁

### 8.1 需求链路

```text
Artifact imported
→ parsed/OCR regions
→ candidates generated
→ human reviewed
→ requirements approved
→ MBSE revision generated
→ baseline approved
```

### 8.2 总体设计链路

```text
Indicator envelope validated
→ historical concepts retrieved
→ 3–5 candidates generated
→ hard constraints checked
→ multidisciplinary runs completed
→ optimization decision prepared
→ concept baseline approved
```

### 8.3 详细设计链路

```text
Design intent parsed
→ ambiguity checked
→ CAD execution plan previewed
→ designer approved
→ CAD revision created
→ annotations generated/reviewed
→ DFM/DFA findings resolved
→ design baseline approved
```

正式状态转换必须由明确动作触发。外部工具回调、后台任务完成或 LLM 输出均不能直接批准对象。

## 9. 错误与恢复设计

- 每次外部调用建立 Job，记录 `queued/running/succeeded/failed/cancelled/timed_out` 状态。
- 外部调用使用幂等键；重复请求不能重复创建 CAD 特征或重复写入正式结果。
- 文档和只读模型分析失败时保留部分成功结果及逐项诊断。
- CAD 写操作采用预览、批准、执行、新版本四步协议，不原地覆盖客户原始模型。
- 批量仿真中单一学科失败不终止其他已独立运行的任务，但综合结论必须显示不完整。
- 代理模型超出有效域、误差登记缺失或版本失效时返回不可用，不降级为无依据预测。
- 审批后输入发生变化时，下游结果标记 `stale`，不得继续显示为当前有效。

## 10. 安全与治理

- Web/API 在多人部署模式下必须启用身份认证、基于角色的权限控制和请求审计。
- 工作区、项目、数据集和工具凭据分开授权；工具凭据不得进入模型提示、页面或普通日志。
- 文件路径必须限制在授权根目录，拒绝符号链接逃逸和未授权绝对路径。
- 默认本地模型；使用远程模型时必须通过项目级策略显式允许，并记录发送字段。
- CAD 执行仅允许注册操作及经过校验的结构化参数，禁止执行任意脚本或自然语言代码。
- 导出包包含数据清单、哈希、审批记录和来源，不自动包含受限原始文件。
- 所有删除动作采用可恢复策略或明确审批，并形成审计事件。

## 11. 内部验收指标

### 11.1 功能点 1.1

- 同一批次成功导入 DOCX、文本 PDF 和扫描 PDF。
- 客户验收集上显式需求提取准确率不低于 85%，召回率不低于 90%。
- 所有输出需求具备文件、页码、区域或段落级来源；来源完整率 100%。
- 隐含约束全部标识为待审核，不发生自动批准。
- 重复导入相同文件不产生重复 Artifact 修订。

### 11.2 功能点 1.2

- 从已批准需求生成 Use Case、活动和时序三类语义模型。
- 用户编辑后重新打开，节点、关系和追溯信息保持一致。
- 需求到用例/活动/消息的追溯覆盖率为 100%，未覆盖项明确列出。
- 交换格式完成导出、导入和语义往返测试。

### 11.3 功能点 2.1

- 对客户指定指标包络生成 3～5 套候选。
- 正式可行候选硬约束满足率为 100%。
- 每套方案包含参数、草图、相似方案依据和可复现信息。
- 相同输入、Profile、模型版本和随机种子得到相同规范化结果。

### 11.4 功能点 2.2

- 正式验收 Profile 至少运行气动、结构、重量/重心三个学科。
- 每次学科执行都保留工具或模型版本、输入哈希、日志和指标。
- 批量执行中一个任务失败时，其他独立任务继续并如实报告。
- 优化输出能够追溯到每个候选的学科结果和约束判定。

### 11.5 功能点 3.1

- 客户验收指令集上，正确生成可执行计划的比例不低于 90%。
- 所有存在歧义的验收指令均触发澄清或明确拒绝，不能静默猜测。
- 未批准计划不修改 CAD；批准计划产生新模型版本和完整操作日志。
- 任一操作失败后能够恢复到执行前模型版本。

### 11.6 功能点 3.2

- 客户关键特性清单中的必需标注覆盖率为 100%。
- 标注数值、单位、标准和目标特征可追溯。
- 二维和三维相同标注的语义值一致。
- 自动布局不得出现影响读取的文字与尺寸重叠；系统检测到无法避让时必须交给人工处理。

### 11.7 功能点 3.3

- 客户植入缺陷集中的高严重度问题检出率为 100%。
- 每个问题包含规则编号、严重程度、模型位置、证据和建议。
- 问题修复后必须重新执行相关规则并形成关闭证据。
- 规则版本变化后，历史审查结果仍可按原版本复现。

## 12. 测试策略

### 12.1 单元测试

覆盖领域状态转换、单位归一化、约束判定、追溯完整性、CAD 操作校验、规则状态和证据哈希。领域测试不连接外部工具。

### 12.2 契约测试

每个端口提供共享契约测试套件，模拟适配器和真实适配器必须通过相同输入输出、错误类型、超时和能力发现测试。

### 12.3 黄金数据测试

客户批准的脱敏文档、历史方案、仿真输入、CAD 模型和植入缺陷组成版本化黄金数据集。预期需求、图模型、可行方案、指标和问题清单由客户或领域专家批准。

### 12.4 集成测试

在受控环境中分别验证 PDF/OCR、MBSE、各学科求解器和 CAD。真实工具版本、许可证和环境信息进入测试报告。

### 12.5 端到端验收

至少选择一个客户场景，完成文档导入、需求批准、场景建模、总体候选、三学科评估、方案批准、CAD 建模、标注、规则审查和证据包导出。任何步骤使用演示结果时，该步骤不得签署正式验收结论。

## 13. 交付里程碑

### M0：验收基线与公共契约

交付统一对象、状态机、端口、客户验收数据清单、功能验收用例和安全策略。出口条件是七项需求都具备可执行的验收用例。

### M1：文档需求闭环

交付 PDF/DOCX/OCR、结构化需求、人工审核和追溯矩阵，完成 1.1 验收。

### M2：MBSE 场景闭环

交付 Use Case、活动图、时序图、编辑和交换，完成 1.2 验收。

### M3：总体候选闭环

交付历史方案库、指标包络、相似检索和 3～5 套布局候选，完成 2.1 验收。

### M4：多学科优化闭环

交付至少三个真实学科适配器或经客户批准的组合、批量调度、代理模型治理和优化反馈，完成 2.2 验收。

### M5：自然语言 CAD 闭环

交付 CAD 中立端口、自然语言意图、澄清、操作计划及至少一种真实 CAD 适配器，完成 3.1 验收。

### M6：图纸标注闭环

交付二维工程图、三维 PMI、尺寸避让、GD&T 和标准配置，完成 3.2 验收。

### M7：设计审查闭环

交付 DFM/DFA 规则库、几何定位、问题管理和复核证据，完成 3.3 验收。

### M8：统一系统验收

交付全链路场景、权限与安全测试、性能测试、部署包、源代码、接口文档、用户文档、培训材料和验收证据包。

## 14. 实施顺序与依赖

1. 先建设 M0；统一对象和证据契约是后续所有模块的前提。
2. M1 和 M2 构成第一个独立实施计划，优先修复当前系统对客户需求文本识别不足的问题。
3. M3 和 M4 构成第二个独立实施计划；启动前客户需提供历史方案字段和学科工具清单。
4. M5、M6 和 M7 构成第三个独立实施计划；启动 M5 真实适配器前需确定客户认可的 CAD 软件及版本。
5. M8 在前三个实施计划均通过模块验收后执行。

CAD 厂商未确定不阻塞 M0～M4。M5 可先完成厂商无关契约、模拟适配器和安全机制，但 3.1～3.3 的正式验收必须在真实 CAD 适配器上完成。

## 15. 现有项目迁移策略

- 保留现有 Artifact、Claim、RFLP、Baseline、Delta、TaskContract、Evidence 和审计数据。
- 为现有工作台增加 schema 版本与迁移函数，不要求用户删除已有工作区。
- 将现有轻量文档读取器作为纯文本/DOCX 基础适配器，新增 PDF/OCR 适配器。
- 将现有静态 RFLP SVG 保留为只读视图；新增语义 MBSE 模型，不用图片替代模型。
- 将现有固定 Candidate 和 Simulation 明确降级为开发示例，不进入总体设计正式 Profile。
- 将现有进程内 Plugin Registry 演进为有能力声明、配置校验和隔离策略的工具注册中心。
- 保持 CLI、Web 和 `/api/v1` 的兼容入口；新增对象使用版本化 API，不静默改变现有响应语义。

## 16. 非目标

本项目不从零开发商业级 CAD 几何内核、CFD/有限元求解器或通用 OCR 基础模型。项目负责受控集成客户认可的真实工具、建设领域数据与智能编排、验证代理模型，并保证从需求到设计证据的统一追溯。

本项目不以自由聊天代替结构化工程模型。自然语言是输入和解释界面，正式对象必须满足领域 schema、状态门禁和版本规则。

## 17. 设计完成判据

设计进入实施计划前必须满足：

- 七项客户功能均映射到明确组件、对象、端口、错误处理、测试和验收指标。
- 三个子系统边界和实施顺序明确。
- 未确定的具体 CAD 厂商被限制为外部集成配置，不影响公共架构，也不被模拟适配器代替验收。
- 文档中不存在未定义的成功状态、无来源的正式结论或允许 AI 自动批准的路径。
- 用户已经书面复核本设计规格。
