# 中文项目名与可编辑创建框设计

## 目标

让中国用户可以在“开始项目”的项目管理页直接点击并编辑项目名称，使用中文创建项目。英文、数字和原有项目仍保持兼容。

## 已确认的问题

- 创建表单当前使用只允许 ASCII 字符的浏览器 `pattern`。
- 后端工作区名称正则也只允许英文、数字、点、下划线和短横线。
- 表单使用默认值，缺少明确的可编辑提示；当前运行中的旧服务还可能没有加载最新项目管理页。

## 方案

采用最小改动方案：

- 前端输入框改为明确的文本输入控件，增加稳定的 `id`、中文占位提示、长度限制和自动聚焦；移除会拦截中文的 ASCII `pattern`。
- 后端允许 Unicode 字母、数字、下划线、点和短横线组成项目名，但首字符不能是点、下划线或短横线，长度限制为 1 至 64 个字符；空格、斜杠、反斜杠和控制字符继续拒绝。
- 不引入“显示名 + ASCII 路径别名”双字段，也不自动把中文转成拼音，避免改变用户看到的项目名和增加迁移成本。
- 保留现有工作区目录结构、路由参数和项目管理流程。修改代码后需要重启 Web 服务，旧进程不会自动加载模板和校验代码。

## 数据流与边界

1. 用户打开项目管理页，项目名输入框自动获得焦点。
2. 用户输入中文、英文或混合项目名并提交。
3. 浏览器只执行必填和最大长度校验，不在客户端用 ASCII 规则拦截中文。
4. 后端统一校验字符安全性，并在工作区根目录下创建同名目录。
5. 创建成功后重定向到该项目的工作区页面；项目名原样显示并用于现有路由。

项目名不允许路径分隔符、控制字符、空名称或超过 64 个字符；重复名称继续返回现有冲突错误，不覆盖已有项目。

## 测试

- 工作区单元测试验证中文名称可以创建并被列出。
- 工作区单元测试继续验证路径穿越、斜杠、空名称和点目录名称被拒绝。
- Web 测试验证创建页输入框具有文本类型、稳定 ID、自动聚焦和中文占位提示，且没有 ASCII `pattern`。
- Web 测试使用中文项目名提交表单，验证返回重定向和实际工作区目录创建。
- 运行工作区、Web 页面和完整相关回归测试。

## 验收标准

用户进入“开始项目”后可以直接点击或自动聚焦到项目名输入框，输入“中文测试项目”并点击“创建并开始”，成功进入该项目页面；已有英文项目、项目路由和安全校验不受影响。
