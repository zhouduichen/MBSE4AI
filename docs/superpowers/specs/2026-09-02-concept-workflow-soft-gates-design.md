# 一键概念工作流软门禁与 LLM 补全设计

## 背景

当前一键概念工作流直接把规则解析结果送入固定翼指标包络。只要缺少任意必需参数，2.1 就失败；历史版本则以 LLM 为核心，允许宽泛输入先形成系统主题、需求候选、架构和概念方案，再逐步补充专业参数。专业领域包和历史方案都应当是增强源，不应成为 LLM 产出的前提。

## 目标

- 任意非空自然语言需求都至少产生一个可查看、可追溯的临时概念产出。
- 现有远程 LLM 分析能力是主流程，负责从任意自然语言形成系统语义、需求、MBSE 草案和概念方案。
- 专业领域包继续提供参数 schema、默认值、公式、约束、候选生成和评估规则，但只在匹配或明确选择时增强 LLM 结果，不成为所有输入的硬前提。
- 规则识别出的明确数值拥有最高优先级；没有历史方案时，LLM 仍可独立生成临时方案。
- 参数来源明确区分 `explicit`、`derived`、`suggested_llm`、`suggested_history` 和 `suggested_default`。
- 低阶评估、推荐基线和正式工程批准继续保持不同状态；软门禁不等于正式验证通过。

## 非目标

- 不实现三维 CAD、PMI/GD&T、DFM/DFA 或正式 CFD/FEA。
- 不让 LLM 覆盖规则解析出的明确数值。
- 不把跨领域输入强行伪装成固定翼物理结论；无法匹配专业包时仍输出 LLM 领域中立的概念方案和补充建议。

## 方案选择

### 方案 A：只放宽必需字段检查

实现最简单，但没有接通历史版本的 LLM 语义补全，任意自然语言仍缺少可靠的领域和参数来源。

### 方案 B：LLM 主导、专业包和历史方案可选增强（采用）

现有领域无关 LLM 分析和 MBSE 草案能力保持主链。规则先提取明确指标，LLM 负责语义理解、需求补全和概念构思；匹配到专业包后再调用现有参数规则、布局生成、学科评估和优化；历史方案只用于检索相似案例。这样恢复历史版本的核心体验，同时保留专业工程能力。

### 方案 C：由 LLM 动态生成全新的领域包

泛化能力最高，但会引入动态 schema、参数规则和评估器验证问题，超出当前一键 Demo 的范围。

## 组件与数据流

```text
非空文本/文档
    ↓
LLM 主导分析：系统上下文、需求、MBSE 草案、概念方案
    ↓
规则解析：提取明确指标并覆盖冲突的 LLM 数值
    ↓
可选专业包匹配：schema、默认值、公式和评估规则
    ↓
可选历史方案检索：相似案例和来源证据
    ↓
确定性合并：explicit > derived > llm_inferred > suggested_history > pack_default
    ↓
专业包可用：指标包络 → 候选生成 → 多学科评估 → Pareto
专业包不可用：保留 LLM 概念方案和 MBSE 草案，不阻断产出
```

### LLM 接入

概念工作流通过依赖注入使用当前激活的 LLM profile 和现有领域无关分析请求。LLM 是概念理解和方案构思的主要来源，返回结构化系统上下文、需求、MBSE 草案、概念候选、参数建议、假设和理由；这些内容进入现有可审核数据结构，不绕过追溯和审核。规则提取结果与 LLM 结果按稳定 ID 合并，明确数值不可被 LLM 覆盖；LLM 推断字段保留置信度和来源。LLM 不可用时才进入规则/专业包降级路径，并明确标记降级状态。

### 指标包络

`RequirementEnvelope` 增加 provisional 生成路径。`required` 字段继续用于正式完整性检查，但不再阻止概念 Demo 生成。若专业包可用，对于专业包候选生成所需字段按以下顺序取值：明确需求、可信公式推导、LLM 推断、历史方案统计、专业包默认值。每个值都写入字段 provenance 和诊断。专业包的参数规则、公式和 hard constraint 仍然执行；软门禁只放宽“信息不完整”，不放宽“参数非法”。若没有匹配专业包，则不强行构造固定翼包络，保留 LLM 的概念方案对象。

### 历史方案

历史方案数量为零时，检索步骤返回空匹配并标记 `history_available=false`，继续执行后续流程。没有历史方案但 LLM 已提供足够结构化参数时，直接使用 LLM 结果和专业包生成候选；没有专业包时直接输出 LLM 概念方案。历史来源只在真实存在时写入 provenance，不伪造历史记录。

### 状态和界面

非空输入的运行不因缺字段进入 HTTP 500。LLM 能生成概念方案时运行状态为 `completed`/`provisional`；匹配专业包时继续显示候选、评估和 Pareto，正式状态保持 `development-only`。没有专业包时显示 LLM 概念方案和 MBSE 草案，不显示伪造的专业评估结论。页面展示每个参数的来源，推荐基线继续使用 `provisional_selected`。

## 异常处理

- LLM 未配置、超时或返回无效 JSON：保留规则结果，依次使用历史和专业包默认值；若仍无法形成专业候选，则输出规则驱动的临时概念草稿。
- LLM 提供越界或未知参数：丢弃该字段并记录诊断，不覆盖有效值。
- 专业包不匹配、历史方案导入失败或没有记录：对应增强步骤降级为空，不阻断 LLM 主流程。
- 空输入、领域包损坏、数据库不可用等运行前提错误仍明确失败；“任何一句需求”不包含空文本或基础设施故障。

## 验收测试

1. 输入“我想做一个适合城市巡检的智能飞行器”，无历史方案、使用 LLM 夹具且不强制指定专业包时，工作流产生结构化需求、MBSE 和 LLM 概念方案，不在 2.1 因缺字段失败。
2. 没有历史方案但 LLM 返回完整参数且匹配专业包时，所有候选参数来源为 `explicit`、`derived` 或 `llm_inferred`，检索为空仍完成专业候选、评估和优化。
3. 没有匹配专业包时，工作流仍保存 LLM 概念方案和 MBSE 草案，不生成虚假的专业评估结论。
4. LLM 不可用且输入只有宽泛意图时，仍产生规则/专业包降级的可查看临时草稿，正式状态不是 `approved`。
5. 输入包含精确数值时，规则值覆盖 LLM 建议值，并保留原有单位换算和追溯 ID。
6. 重复输入产生稳定的运行 ID、结果哈希和建议字段来源。
7. 现有专业包、固定翼完整需求、历史方案导入、概念评估和全量回归测试保持通过。
