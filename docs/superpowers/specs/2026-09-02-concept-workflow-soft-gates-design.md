# 一键概念工作流软门禁与 LLM 补全设计

## 背景

当前一键概念工作流直接把规则解析结果送入固定翼指标包络。只要缺少任意必需参数，2.1 就失败；历史版本则允许宽泛输入先形成系统主题、需求候选和草稿模型，再逐步补充。历史方案应当是检索增强数据，不应成为生成前提。

## 目标

- 任意非空自然语言需求都至少产生一个可查看、可追溯的临时概念产出。
- 已配置远程 LLM 时，使用现有领域无关分析能力补充系统语义、领域判断和缺失参数；规则识别出的明确数值拥有最高优先级。
- 没有历史方案时，仍可仅依靠 LLM 生成结构化参数并继续候选生成。
- 参数来源明确区分 `explicit`、`derived`、`suggested_llm`、`suggested_history` 和 `suggested_default`。
- 低阶评估、推荐基线和正式工程批准继续保持不同状态；软门禁不等于正式验证通过。

## 非目标

- 不实现三维 CAD、PMI/GD&T、DFM/DFA 或正式 CFD/FEA。
- 不让 LLM 覆盖规则解析出的明确数值。
- 不把跨领域输入强行伪装成固定翼物理结论；无法形成领域参数时仍输出领域中立的概念草稿和补充建议。

## 方案选择

### 方案 A：只放宽必需字段检查

实现最简单，但没有接通历史版本的 LLM 语义补全，任意自然语言仍缺少可靠的领域和参数来源。

### 方案 B：接通现有领域无关 LLM 流程并启用软门禁（采用）

规则先提取明确指标，复用现有激活的 LLM 配置补充语义和建议参数，历史方案作为可选增强源，领域包默认值作为最后回退。它能恢复历史版本的体验，同时不复制现有 LLM 和概念设计算法。

### 方案 C：由 LLM 动态生成全新的领域包

泛化能力最高，但会引入动态 schema、参数规则和评估器验证问题，超出当前一键 Demo 的范围。

## 组件与数据流

```text
非空文本/文档
    ↓
规则解析：保留原文、明确指标、来源区域
    ↓
领域无关 LLM 分析：系统上下文、候选需求、补全参数
    ↓
确定性合并：explicit > derived > suggested_llm > suggested_history > suggested_default
    ↓
软门禁指标包络：允许 provisional envelope
    ↓
MBSE → 历史检索（可为空）→ 候选生成 → 多学科评估 → Pareto → 临时推荐
```

### LLM 接入

概念工作流通过依赖注入使用当前激活的 LLM profile 和现有领域无关分析请求。LLM 只返回结构化候选，不直接写入最终 Requirement。规则提取结果与 LLM 结果按稳定 ID 合并，明确数值不可被 LLM 覆盖；LLM 补全字段保留假设、置信度和来源。

### 指标包络

`RequirementEnvelope` 增加 provisional 生成路径。`required` 字段继续用于正式完整性检查，但不再阻止 Demo 生成。对于候选生成所需字段，按以下顺序取值：明确需求、可信公式推导、LLM 建议、历史方案统计、领域包安全默认值。每个回退值都写入字段 provenance 和诊断。

### 历史方案

历史方案数量为零时，检索步骤返回空匹配并标记 `history_available=false`，继续执行后续流程。没有历史方案但 LLM 已提供足够结构化参数时，直接生成候选；两者都不足时，生成领域中立的临时概念草稿，不伪造历史来源。

### 状态和界面

非空输入的运行不因缺字段进入 HTTP 500。可生成候选时运行状态为 `completed`，正式状态保持 `development-only`；只能生成领域中立草稿时仍保存工作流、需求、MBSE 和诊断，并显示 `provisional`/“待补充参数”。页面展示每个参数的来源和“系统建议”提示，推荐基线继续使用 `provisional_selected`。

## 异常处理

- LLM 未配置、超时或返回无效 JSON：保留规则结果，依次使用历史和领域包默认值；无法形成物理候选时保存临时草稿和可读诊断。
- LLM 提供越界或未知参数：丢弃该字段并记录诊断，不覆盖有效值。
- 历史方案导入失败或没有记录：检索降级为空，不阻断主流程。
- 空输入、领域包损坏、数据库不可用等运行前提错误仍明确失败；“任何一句需求”不包含空文本或基础设施故障。

## 验收测试

1. 输入“我想做一个适合城市巡检的智能飞行器”，无历史方案，使用 LLM 夹具响应时，工作流有结构化需求、临时包络、候选或领域中立草稿，且不在 2.1 因缺字段失败。
2. 没有历史方案但 LLM 返回完整参数时，所有候选参数来源为 `explicit`、`derived` 或 `suggested_llm`，检索为空仍完成后续流程。
3. LLM 不可用且输入只有宽泛意图时，仍产生可查看草稿/默认建议值，正式状态不是 `approved`。
4. 输入包含精确数值时，规则值覆盖 LLM 建议值，并保留原有单位换算和追溯 ID。
5. 重复输入产生稳定的运行 ID、结果哈希和建议字段来源。
6. 现有固定翼完整需求、历史方案导入、概念评估和全量回归测试保持通过。
